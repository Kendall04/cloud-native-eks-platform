This is a dated, sanitized handoff, reconciled from the existing private receipts and the 29 October cost-down summary. No new AWS observation or deployment is claimed by this document.

## Demonstrated behavior

The three .NET 10 services ran on private EKS 1.35, with six base Ready replicas and PostgreSQL 15.18. Real authentication, resource authorization, shipments and tracking were exercised. Two tracking sequences retained logical identity through transactional outbox, EventBridge, standard SQS and Shipment's durable inbox and persisted updates.

GitHub manual Build, Create Release and Deploy completed the private OIDC → immutable artifacts → SSM → management → Helm path. Release v2.0.8 reached Helm revision 4. An earlier strict smoke failure on HTTP 504 triggered a verified automatic rollback; the later successful delivery used Pod Readiness Gates confirmed against the exact new ALB target IPs. The HTTP failure is not evidence that Auth itself caused the timeout. Helm recovery does not undo database migrations.

One NAT ASG member replacement recovered its stable EIP and route in 178 seconds on the controller revision installed for this cycle. This observation is not certification of later controller source changes. Private egress after that replacement remains UNVERIFIED; continuous egress and cross-AZ failover were not demonstrated. Node placement A/A/C was a snapshot, not a scheduler guarantee. RDS was Single-AZ.

The public browser trial used the existing portfolio hosting, first synthetic DEMO, then the explicit AWS edition, then DEMO again. Real browser authentication, business data and asynchronous updates were checked. Return to DEMO removed API forwarding and discarded the previous memory session. It does not demonstrate rollback between two different authenticated AWS application versions.

The retained RDS source intentionally has no EKS/management dependency or allowed source SGs after cost-down. Before a future authorized rebuild, restore dependencies to the **new current** EKS/management SG outputs and review a native plan limited to required PostgreSQL ingress. No historical SG ID is an approved substitute. Do not change the DB, protection, parameters, backups or credentials as a networking shortcut.

The local NAT activation commit was specific to this cycle and is not a reusable default. Retain its generation/approved predecessor history; do not apply it blindly after cost-down. Reconcile CONTROL, generation, READY journals and actual new predecessor ownership first.
